# CBPC nominal callback proposal

Unqualified source protocol. It has not been installed, frozen as a runnable case
or launched. Old pulse protocols and their failed case02/03
records are unchanged and must not be rescored under this separate nominal
contract (`claw-cbpc-animated-nominal-proposal/1`).

The only entry point is `cbpc_nominal_owned_case.run` in an already owned SE
Session. The operator still supplies an independently frozen female disposable
born-wolf fixture, fresh admitted observer packet, declared subject pins and
the pinned stock-role expected document. There is no CLI, launch script,
installation step, provider-state getter or new observer API.

## Source checks and prerequisites

The pure metric tests in `src/test/python/physics/test_cbpc_nominal.py` belong
to the ordinary offline suite. The recorded transport tests live separately in
`src/test/python/integration/test_cbpc_nominal_owned_case.py`: explicitly provide
the qualified `skyrim_autotest` Python package through `PYTHONPATH` before running
that test. This is a declared integration dependency, not an implicit launcher or
an additional prerequisite for the default physics suite.

Fixture source paths use repository-relative or logical `mod:`, `repository:`
and `evidence:` anchors. Their provenance records retain the original hashes;
the normalized stock-role fixture has its own separately recorded hash. These
anchors are not live file admissions. A real case must create fresh actual
input paths, hashes and VFS proofs rather than dispatching the offline fixture.

## Admission and source boundaries

The outer case must first verify the actual VFS winners, loaded CBPC/observer/
CLAW modules, absent competing writers, nearby fixture ownership and the complete
stock configuration/conditional-controller proof. Use the existing case03
admission recipe; a copied old proof is not new live admission. The callback
checks the four declared helper source hashes, XP32 hash and actual pinned stock
expected document, then repeats the existing loaded-root role qualification.

The proposed `cbpc_probe.completed` has one additional guard: a result carrying
`isError` cannot count as completed. This is a shared native-return shape check,
not a changed old metric. The external proposed subject-pin document records
the new helper hash and original source/hash separately. Actual DLL, master,
script, skeleton and raw contract provenance remain unchanged. The original
helper hash is retained separately from the successor's guarded implementation;
the original external `subject-pins.json` and old raw cases remain unchanged.

Before the first mutation, live Papyrus descriptors must declare these exact
native signatures and return types:

| Scope | Function | Parameters | Return |
|---|---|---|---|
| CBPCPluginScript global | StartPhysics / StopPhysics | Actor, string | none |
| Actor member | EnableAI / SetRestrained | bool | none |
| ObjectReference member | SetPosition | float, float, float | none |
| ObjectReference member | Disable | bool | none |
| Game global | GetCurrentCrosshairRef | none | ObjectReference |

The null value of GetCurrentCrosshairRef is actually returned with native
`returnedType="none"`. A descriptor return type alone does not prove a call
completed. Recorded case02/03 packet-shape fixtures are provided with provenance;
they are not nominal observations or new game evidence.

## Finite collection and uncertainty

The callback issues completed EnableAI(true) and SetRestrained(true) requests,
then exact Start all11 / Stop all11 / Start all11 requests. Those void returns do
not observe previous AI/provider state, binding or current solver ownership.
Each window settles for at least two measured seconds and follows the declared
25-position actor-X trajectory, giving exactly 24 observed inter-sample gaps.
The target period remains .85 seconds, allowed jitter .15, amplitude .5.

Only the actor reference is translated. There are no node, NiOverride, race,
scale, morphology or provider-file writes. Every SetPosition uses literal float
arguments, a durable intent, exactly one dispatch, exact completed receipt and
fresh actual reference/root readback. The scorer requires all75 position
receipts; the sampled window must be the receipt's actual after-observation.

Host QPC schedules samples; Session's monotonic clock bounds transport. Every
Session.tool call receives an absolute deadline. The 160-second aggregate
callback bound reserves 32 seconds for normal cleanup; no active collection
uses that reserve. Actual producer cadence and trajectories, rather than host
sleep requests, determine acceptance. Slow or incomparable observations fail
without adjusting the contract.

Before every further mutation, the preceding mutation must have a durable
completed receipt and actor/root continuity must be freshly observed. Unknown
return, transport failure, KeyboardInterrupt/SystemExit or cancellation
quarantines this callback. It makes no further transport calls or actor/provider
cleanup writes. In particular it does not guess Stop/Start, restore position or
Disable after an uncertain dispatch. The owner must tear down the exact owned
disposable world through the existing Session lifecycle.

Do not reuse case03's unconditional outer `dispose_fixture` finally block around
this callback: disposal is already owned here, and that old outer block would
dispatch another mutation after uncertainty. The outer wrapper owns normal
Session process exit and exact file/profile preimage restoration, not duplicate
actor/provider controls. Persisted intent/quarantine state must survive failure.

## Cleanup and claim

On normal completion, or a known-completion failure with intact identity and no
cancellation, cleanup restores the observed actor origin, verifies it, disables
only the guarded disposable NPC and observes disabled state plus null crosshair.
Disable is never replayed while polling those readbacks. Provider/AI prior state
is unknown and no provider-state restoration is claimed. Absolute bone poses are
never restored. Cleanup errors remain failures and require owned Session teardown.

The pure scorer's `fixtureCleanupVerified` means only origin restoration and
disabled identity. It now names that scope explicitly. Crosshair release is an
additional callback observation; normal exit, no owned processes and exact
preimage restoration are separate outer Session gates.

All existing nominal numeric gates remain: each driver must show on/off/on
contrast in the same own-local and pinned-expected-parent-relative world
channel, with quiet stopped output and own-local controls, comparable actual
kinematic input and cadence, expected transform composition and native float32
grid/ULP-derived floors. Parent identity is not directly observed. Unsynchronized
samples and conservative large-coordinate floors can leave real motion
unconfirmed. The result remains `runtimeQualified=false`; it cannot establish
impulse response, physical fit, contact, aesthetics or general graph identity.

Before any runnable case, independently review this source, freeze exact callback,
helper, Session/API and fixture/provider inputs, and obtain operator custody and
launch authority separately. Source/unit tests do not grant that authority.
