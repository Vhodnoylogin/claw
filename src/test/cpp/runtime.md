# Preset companion runtime acceptance

This is a scenario/oracle contract, not an executable Polygon order and not a
record of passing tests. Run it in the CLAW chat only after the testing-tool chat
has qualified the actual VR provider/action/readback path. A cached status2 or a
successful setter is insufficient evidence of a visible body change.

## Candidate and controls

Use a separate test profile/save and the pinned published0.6.2.0 base, its actual
dependencies, the separately packaged companion and four example XML presets.
Keep experimental geometry, breast rig, physics, Anatomy and VR bodies out of
this first test so failures can be attributed. Verify the winning virtual paths
and loaded DLLs, not just files in an inactive mod directory. Record the actual
runtime, catalog, plugin/PEX/DLL/XML hashes and game-session owner.

Use two disposable male and two disposable female werewolf references. Record
reference/base IDs, current race, base sex/weight, loaded3D and actual body/TRI
paths before interpreting morph results. Include a human control with an OBody
assignment and an independently owned sentinel morph contribution. Own all
fixture writes and retain a cleanup ledger. Do not modify another mod's key.

## Bounded scenarios

1. **Discovery and independent assignment.** With no manual request, each loaded
   beast receives a preset from its own typed family. A newly encountered unloaded
   actor has not necessarily received an assignment yet: selection occurs after
   loaded3D is checked. Test preservation across reload on an actor whose preset
   was already applied. A human keeps its OBody assignment and is absent from the CLAW
   automatic pool. Catalog names match the separately installed XML exactly.
2. **Selector and invalid request.** Open the actual selector for each sex and
   choose both examples. Verify selection, own coefficients and rendered change.
   The filtered menu cannot select a wrong-family preset. Use the separately
   qualified native-call transport for that negative case: an accepted queue
   request is not application, and must subsequently report status4/error,
   retain the previous valid selection and preserve its error through passive scans.
   Do not call Refresh while observing this: it is a new request that replaces
   the error. Internal pin release is not observable through public getters.
   A later valid request replaces that error. Automatic scans must not erase the
   failure receipt. Menu selection is tested through the menu, not substituted
   with a native call.
3. **Endpoint interpolation.** Weight belongs to ActorBase, not an independent
   spawned reference. Use different fixture bases or change a shared base
   sequentially with an explicit restoration record. At weights0,50,100, compare every recognized
   coefficient against the XML's linear small/big interpolation, once only.
   Omitted endpoints and omitted morphs are zero. Inspect actual SKEE own-key
   values independently of GetOwnMorph's cache, and confirm a selected nonzero
   ear/tail morph changes the actual loaded mesh or an independently qualified
   rendered observation. Identical base `_0`/`_1` meshes are expected.
4. **Other owners and OBody.** Put the fixture-owned foreign sentinel on the
   very beast being assigned/cleared; a human-only sentinel is insufficient.
   Snapshot human preset identity and both actors' sentinel values;
   exercise CLAW assignment/refresh/clear and an ordinary respectful OBody update.
   They must retain every foreign contribution. After clearing CLAW, the beast
   may still look modified by that foreign contribution. Record aggregate-morph policy
   separately from own-key values; do not assume addition. The companion must
   not silently change OBody settings. Non-respectful OBody clearing all owners
   is a documented external conflict, not successful coexistence.
5. **Clear and lifecycle.** ClearOwn zeros only CLAW.Distribution and persists
   automatic suppression through scans, 3D reload and save/load. AssignPreset
   explicitly resumes it. With an active preset, unload/reload3D and rebuild the
   model without rerolling. ClearOwn keeps the selected name but suppresses its
   application. Returning to human clears the own key; returning to
   beast restores the saved beast selection while preserving the human preset.
6. **Persistence and identity.** Save/reload with multiple same-base references
   and manually chosen distinct selections; random automatic choices need not
   differ. Their choices remain per-reference. Delete a
   disposable actor with a queued request, then create another of the same base;
   the old request must not alter the new actor. Record actual IDs and timing;
   this is not proof of FormID or VM-handle reuse unless reuse was observed.
   An unavailable/mismatched saved identity must produce a log diagnostic and no
   inherited morph write. Ordinary 3D reload must not trigger that quarantine.
   An unbound/quarantined State does not guarantee a public status4/error getter.
   The existing fixture transformation spell returns specifically to NordRace;
   do not treat it as restoration of an arbitrary original human race.
7. **Unavailable dependency/catalog.** In a separate bounded restart, omit the
   SKEE provider or introduce one invalid typed XML. Verify the declared failure
   state, no partial catalog assignment, useful logs and no crash/foreign write.
   Without SKEE its independent getter is unavailable; do not fabricate a zero
   readback. Invalid XML at startup does not promise clearing old values already
   retained in an existing save. Both cases need separate process starts because
   provider exchange and catalog loading occur at startup.
   Restore the exact prior profile/files afterward; do not corrupt the live
   installation to manufacture this case.

## First attempt subset

Keep the first bounded game attempt to one loaded male beast, one loaded female
beast and a human/OBody control. Verify current identities/sex/race/base weights,
the four expected names and typed automatic assignments. Exercise the real F8
selector with both examples for each sex, independent own-key reads and a
qualified visible ear/tail observation. On one of those beasts, test foreign
sentinel preservation, ClearOwn/status6/own zeros through passive scans, then a
valid explicit assignment to resume application. Clean up and restore the save.

Save/load, forced3D reconstruction, transformation, weight endpoints, deletion
timing and startup-negative fixtures are later bounded sets. If the generic
invoker, real UI route or render oracle is unqualified, retain the corresponding
assertion as unavailable; do not convert a smaller coefficient-storage smoke
into complete preset acceptance. A failure does not silently authorize a replay.

## Evidence and cleanup

Keep raw action replies, logs, independent own/foreign-key snapshots, catalog
readback and the actual rendered/mesh evidence with timestamps and actor IDs.
Record each assertion's available oracle; mark unsupported renderer/identity
reuse checks unverified. A UI failure or missing loaded TRI is not a passing
coefficient-storage test. Do not transfer these outcomes to SE/AE or experimental
body/physics candidates.

Remove only fixture-owned keys, references and files, restore the pinned profile
and starting save, then verify no active session, pending cleanup or unexpected
installation difference remains. Report an incomplete test when a required
oracle or cleanup step fails. Historical photography orders are never resumed.
